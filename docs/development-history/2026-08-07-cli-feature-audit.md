## 감사 목적

메인 화면과 작품 우클릭 메뉴를 단순화한 뒤에도 기존 기능이 사라지거나 잘못 연결되지
않았는지 CLI로 하나씩 확인했다. 단순히 파서가 명령을 받아들이는지만 보지 않고 다음
수준을 구분했다.

1. 모든 CLI leaf 명령의 실제 프로세스 진입
2. 읽기 전용 상태·계획·dry-run과 로컬 fixture
3. TEMP 복사본의 설정·DB·생성·이동·정리 실행
4. 실행 중인 PyQt GUI에 대한 IPC와 창 열기·닫기·캡처
5. 외부 요청 없는 YouTube 모의 작업
6. 제한된 toki 다운로드와 Hitomi 공개 메타데이터 라이브 요청

사용자 설정, 작업 DB와 다운로드 폴더를 변경하는 검사는 Git `HEAD`를 시스템 TEMP에 푼
복사본에서 실행했다. 복사본은 실제 GUI와 IPC 이름이 겹치지 않도록 기존 GUI를 먼저
종료한 뒤 사용했고, `.venv`와 `node_modules`만 정션으로 재사용했다.

## 전체 CLI 표면

argparse 트리를 재귀적으로 열어 실행 가능한 leaf 명령 201개를 찾았다. 각 경로를 별도
`python toki_app.py <경로> --help` 프로세스로 실행한 결과 201/201이 종료 코드 0이었다.

기능 실행은 위험도에 따라 나눴다.

| 기능군 | 결과 | 실행 수준 |
|---|---:|---|
| 상태·조회·계획 | 64/64 | 실제 저장소, 읽기 전용 |
| Hitomi·YouTube 계획과 확인 경계 | 24/24 | fixture·정상 차단 |
| 내보내기·파일 검사·dry-run | 33/33 | 실제 저장소, 파일 변경 없음 |
| 설정 변경 명령 | 41/41 | TEMP 설정만 변경 후 복원 |
| GUI 창·메뉴·제어 | 46/46 | TEMP PyQt GUI와 실제 IPC |
| 확인이 필요한 보안·삭제 경계 | 19/19 | `--yes` 없는 호출 정상 차단 |

초기 실행에서 실패처럼 보였지만 버그가 아니었던 항목도 분리했다.

- `list-state --preview`는 화면 상태를 바꾸므로 `--apply-gui`가 함께 필요하다.
- `.svg`는 이미지 변환 제외 확장자 목록에 지원되지 않아 정상 거부된다.
- 트레이를 끈 상태의 `tray hide`는 숨길 트레이가 없어 정상 거부된다.
- 로컬 API의 상태 경로는 `/status`가 아니라 문서화된 `/v1/status`이다.
- YouTube mtime 적용은 해당 정책을 먼저 켜야 한다.

- jobs export, import dry-run·실행과 대기 작업·실행 이력 실제 복원

## 발견하고 수정한 문제

### GUI가 꺼진 상태의 작품 폴더 열기

`open-folder --job 작업ID`는 GUI가 실행 중일 때만 해당 작품 폴더를 열었다. GUI가 꺼져
있으면 작업 ID를 무시하고 기본 outputDir를 열었다.

로컬 fallback도 작업 ID로 DB 기록을 읽어 `output_path`, 없으면 `output_dir`를 열도록
수정했다. 없는 ID는 기본 폴더로 조용히 대체하지 않고 오류로 처리한다.

### 설치 검사 한글 출력

`toki-cli.cmd doctor --json`은 정상이지만 `setup-gui.cmd -CheckOnly`를 거치면 DB
마이그레이션 이름이 깨졌다. `setup-gui.ps1`의 Python 자식 프로세스에 UTF-8 모드와 출력
인코딩을 고정했다. 같은 설치 검사를 다시 실행해 한글과 필수 의존성 5/5를 확인했다.

### 없는 재시도·재검사 ID의 거짓 성공

GUI IPC의 `retry`와 `rescan`은 명시한 작업 ID가 없을 때 `null`을 반환하고 CLI 종료 코드는
0이었다. 이제 ID를 포함한 명확한 오류를 반환한다. 실제 GUI에서 존재하지 않는 ID로
재시도해 종료 코드 1을 확인했다.

### 파일 도구 결과창 닫기 CLI

파일 검사와 이미지 미리보기는 CLI로 결과창을 열 수 있었지만 닫을 수 없었다. 이 때문에
자동 캡처가 메인 창 대신 이전 결과창을 계속 찍었다.

다음을 추가하고 실제 GUI에서 `closed=true`를 확인했다.

    toki-cli.cmd verify-files --close
    toki-cli.cmd preview --close

## 로컬 환경 변경과 제한

- pHash와 7Z/RAR 검사를 위해 프로젝트 `.venv`에 `ImageHash`, `py7zr`, `rarfile`과 해당
  의존성을 설치했다. Git 추적 파일은 바뀌지 않는다.
- doctor의 선택 도구는 7/9 사용 가능하다. FFmpeg와 PyInstaller는 설치하지 않았다.
- YouTube 실제 미디어 다운로드는 실행하지 않았다. yt-dlp 계약과 모의 작업은 검증됐지만
  실제 영상·오디오 결합은 FFmpeg가 필요한 별도 라이브 검사다.
- 시스템 클립보드, 기본 브라우저·탐색기, 공개 IP 조회, 시스템 종료, 실제 쿠키·프록시
  자격증명과 토큰 회전은 개인·OS 상태를 바꾸므로 실제 실행하지 않았다. 파서, 확인 경계,
  IPC payload와 단위 테스트로 검증했다.
- 합성 CB7은 검사했지만 RAR/CBR 표본은 만들지 않았다.
- toki 신규·전체 검사는 각각 271·272개를 선택하는 것까지 확인하고 대량 다운로드 전에
  중지했으므로 전 회차의 라이브 다운로드 완료 검사는 아니다.
- 외부 사이트 구조와 도메인은 이후 바뀔 수 있으므로 라이브 결과는 2026-08-07 기준이다.
