# 2026-09-08 원본 회차 폴더의 정렬 순번

## 문제와 변경

사용자가 지정한 이세계 개인방송 작품 폴더에는 `0001 축약 제목 1화`와
`전체 제목 2화` 형식이 섞여 있었다. 제목이 정렬 키의 앞에 있으므로 표기 변경에 취약하고,
문자열 정렬을 사용하는 뷰어에서는 2화보다 10화가 먼저 나올 수도 있었다.

- 새 회차 폴더의 기본 저장명: `000001 전체 제목 1화`.
- 앞의 6자리 번호는 사이트 전체 회차 목록의 읽기 순번이다. 실제 회차 표기는 끝에 유지한다.
  `000025 전체 제목 25-1화`, `000026 전체 제목 25-2화`처럼 분할 회차도 순서가 유지된다.
- 전체 제목 복원, 소수 회차가 있을 때만 기본 회차의 `.0`, 분할 `-2`가 있을 때의 `-1`
  처리는 기존 공용 접미사 규칙을 그대로 사용한다.
- `rename-episodes`와 GUI의 회차 폴더명 정리 기본값도 동일한 `ordered_title` 규칙이다.
  과거 title-only 이관 코드는 내부 `ordered=False` 호환 모드와 기존 회귀 검사로 보존한다.
- 기존 폴더를 다운로드 도중 몰래 이동하지 않도록 재개 시 존재하는 매핑은 재사용한다.
  다른 작품의 예전 폴더는 사용자가 해당 작품의 회차 폴더명 정리를 실행하면 일괄 변경된다.
- 실제 이관은 기존 두 단계 이름 변경/복구 절차를 사용한다. 상태·메타데이터뿐 아니라
  ZIP 카탈로그도 백업하고 원본 폴더 참조를 함께 바꾼다. ZIP 파일 내용은 변경하지 않는다.
- 충돌이나 카탈로그 저장 실패 시 폴더 및 메타데이터·카탈로그를 복구한다.

## 검증 및 실제 적용

- 변경 시점의 사용자 작업 ID `72fcae5824`에서 실제 CLI `rename-episodes --execute --yes --json` 실행.
- 127개 대상, 충돌 0, 실제 127개 변경. 재검토 시 추가 이름 변경 0개.
- 변경 전후 이미지 1,301장 SHA-256 집합(중복 포함) 전부 동일.
- 파일 검사: 원본 회차 127, ZIP 회차 127, 원본/ZIP 이미지 각 1,301.
  누락·손상·중복·미등록·0바이트·문제 모두 0, healthy=true.
- 신규 회차 검사 작업 `5e027dcb71`: 2페이지·127개 재수집,
  기존 완료 127개를 정상 건너뛰고 새 다운로드 없이 종료 코드 0.
- Python 409건, Node 72건 회귀 검사. 실제 격리 CLI, 동일 이름 재실행,
  목적지 충돌 보호, 카탈로그 저장 실패 롤백, 이름 변경 후 ZIP 원본 정리까지 검사한다.
- 전체 회귀 실행에서 기존 CLI 통합 테스트의 간헐적 연결 오판도 재현했다.
  격리 IPC 추적 결과 `ping: GUI에 명령을 보내지 못했습니다` 뒤 오프라인 경로를 타고 있었다.
  Windows에서 빠르게 전송이 끝난 경우 `waitForBytesWritten` 반환값만으로 실패를 단정하던
  문제를 수정했다. 전송 큐가 비었으면 이미 수신된 응답을 읽고, 실제 전송 대기는 시간 초과로
  처리해 GUI 부재로 오판하지 않는다. 두 회귀 테스트와 실제 CLI 통합 검사로 확인한다.

```powershell
.\toki-cli.cmd rename-episodes --job 작품ID --dry-run --json
.\toki-cli.cmd rename-episodes --job 작품ID --execute --yes --json
.\toki-cli.cmd verify-files --job 작품ID --json
```

탐색기/외부 뷰어에서는 이름 오름차순 정렬을 사용한다. 수정일·크기순은 이 규칙과 다르다.
앞 순번은 최대 999999까지 지원하고, Windows 경로 길이를 초과하는 제목은 임의로 자르지 않는다.
