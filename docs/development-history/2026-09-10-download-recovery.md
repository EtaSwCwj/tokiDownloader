## 원인과 수정

### 번호 없는 회차 때문에 작품 전체가 중단됨

쿠로이와 메다카, 히토너, 원펀맨의 일부 실제 목록 제목은 작품명만 있거나 화수 없는 제목이었다.
기존 코드는 전체 회차 매핑을 만들 때 빈 회차 접미사를 오류로 처리해 정상 회차까지 시작하지 못했다.

- 제목이 존재하면 회차 번호가 없어도 허용한다. 비어 있는 목록 제목 자체는 계속 오류로 처리한다.
- 기존 6자리 사이트 순번을 정렬 기준으로 사용한다. 예: `000001 히토너`, `000011 원펀맨 리메이크`.
- 임의의 화수를 만들지 않고 `sourceTitle`, `sourceId`, `sourceUrl`을 보존한다.
- 같은 제목인 두 회차도 각 순번과 고유 ID로 구분한다. 소수·분할 형제 회차 규칙은 유지한다.
- Python 회차 폴더 정리 미리보기도 같은 정책을 사용한다. 순번 없는 레거시 제목 전용 이관은 충돌을 막기 위해 여전히 차단한다.
- 이번 유지보수에서는 기존 사용자 회차 폴더의 일괄 변경을 실행하지 않았다.

### 정상 JPEG 뒤 부가 데이터를 손상으로 오판

울퉁불퉁 마녀 모녀의 사정 25화의 `image0024.jpg`는 JPEG 종료 마커 뒤에 46바이트가 붙어 있었다.
파일은 641,788바이트이고 실제 디코딩 결과는 1512×2150이었다. 기존 검사는 마지막 2바이트만 확인해 거부했다.

- 일반 JPEG는 기존의 가벼운 헤더·끝부분 검사 경로를 유지한다.
- 끝이 특이한 경우에만 마지막 64KiB에서 종료 마커를 찾고 엄격한 전체 디코딩을 수행한다.
- `jpeg-js@0.4.4`를 고정 의존성으로 추가했다. 입력 128MiB, 해상도 64MP, 디코더 메모리 256MiB 상한을 적용한다.
- 이 검사는 GUI 스레드가 아니라 Node 다운로더에서 실행한다. 원본 바이트는 자르거나 변환하지 않는다.
- 다운로드 저장과 기존 파일 재사용 검사에 동일하게 적용한다. 가짜 종료 마커나 잘린 이미지가 기존 정상 파일을 덮어쓰지 않도록 테스트했다.
- 디코더 옵션 기준: [jpeg-js 공식 문서](https://github.com/jpeg-js/jpeg-js).

문제 이미지 SHA-256: `f784c7fa5d907388c4b21dc6381cb36d1a5bfba88ebb8061275738d50b60a0c4`.

### OneDrive 경로의 진행 기록 교체가 일시적으로 거부됨

TSUYOSHI와 일일외출록 반장은 회차 이미지 저장 후 `.toki-state.json` 교체에서 `EPERM`으로 중단됐다.
권한과 읽기 전용 속성은 정상이었고 OneDrive 동기화 경로였지만, 과거 잠금의 주체를 특정한 것은 아니다.

- `downloader_files.js` 공용 파일 교체 재시도를 추가했다.
- `EPERM`, `EACCES`, `EBUSY`에 한해 최대 9회 시도한다. 대기는 100/200/400/800/1000/1000/1000/1000ms, 총 5.5초다.
- 비동기 대기로 이벤트 루프를 막지 않는다. 디스크 용량 부족 등 다른 오류는 즉시 보고한다.
- 진행 기록은 PID와 UUID가 포함된 새 임시 파일에 쓰고 fsync 후 교체한다. 이전 `.tmp` 파일을 덮어쓰지 않는다.
- 교체 실패 시 기존 진행 기록을 삭제하지 않으며 새 임시 기록 경로도 오류 진단에 남긴다.
- 이미지 교체도 같은 재시도를 사용한다. 기존 정상 파일을 먼저 삭제하는 우회는 사용하지 않는다.
- 실제 권한 부족이나 계속 유지되는 잠금은 이 재시도만으로 해결되지 않는다.

해당 페이지(`/manhwa/40/1674773`)는 본문 대신 `이미지 처리 중인 회차입니다. 잠시 후 다시 확인해주세요.`라는 안내를 반환했다.
앞뒤 회차인 은혼 562화와 564화는 각각 이미지 17개를 위한 본문 데이터를 가지고 있었다.
즉 파일 잠금·이미지 형식 문제와 별개의 사이트 원본 준비 상태였으며, 기존 코드는 안내를 인식하지 못하고 작품 전체를 멈췄다.

### 처리 계약

- `downloader_episodes.js`에서 본문 이미지 또는 **관찰된 정확한 준비 중 안내**를 기다린다.
- 이미지가 존재하면 이미지를 우선한다. 인증 오류, 일반 로딩 문구, 알 수 없는 빈 페이지는 준비 중으로 추정하지 않는다.
- 준비 중이면 고유 회차 ID, 원래 제목·URL, 사유, 확인 시각을 `pendingEpisodes`에 즉시 저장하고 다음 회차를 계속한다.
- 해당 ID를 완료 집합에 추가하지 않는다. 나중에 신규 검사에서 다시 선택되며 실제 성공하면 미완료 기록을 제거한다.
- 범위 밖에 남은 미완료 기록도 보존한다. 이전에 완료한 로컬 회차는 전체 검사 중 원본이 준비 중이어도 지우거나 완료 취소하지 않는다.
- 미완료가 남으면 마지막에 `episodes_pending` / `source` / `retryable: false` 오류를 보고한다. GUI의 기존 오류 상태에서 `원본 상태` 및 `일부 미완료` 이유를 표시한다.
- 정상 `completed` 이벤트를 내지 않으므로 자동 압축·원본 정리·자동 PDF는 실행하지 않는다. 전체 작품의 100% 완료로 표시하지 않는다.
- GUI에 `episode_deferred` 기록을 연결하고 진행률·실행 기록은 보류 항목을 성공 건수에서 제외한다. 즉각적인 전체 반복 재시도 대신 다음 작품을 진행한다.
- 사이트가 이미지를 실제 제공하기 전에는 해당 회차 자체를 받을 수 없다. 자동 장기 감시는 추가하지 않았다.
