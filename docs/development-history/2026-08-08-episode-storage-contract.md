# 2026-08-08 회차 저장 계약 수정

## 기준

- 날짜: 2026-08-08 KST
- 시작 기준 커밋: `6360616`
- 종료 커밋: 이 문서를 포함한 커밋
- 관련 계획 단계: 단계 4 다운로드 폴더와 파일 도구

## 해결하려던 사용자 문제

완료 작업 `54d3f0ed91`은 272개 회차와 이미지가 모두 있었지만, 회차 폴더가
`0001 남녀비 139의 …로 평범 1~5화`처럼 생성됐다. `0001`은 실제 1화가 아니라 사이트의
게시물 순번이고 `…`는 사이트 목록 DOM에 이미 들어 있던 축약 문자열이었다. 본편, 합본,
소수 회차와 R-18 외전이 섞인 작품에서 이 이름은 기존 감상 도구의 자연 회차 정렬과 맞지
않았다. 기대 형식은 숫자 접두어 없이 `전체 작품명 + 실제 회차/부제`를 쓰는 폴더와
`0000.ext`부터 시작하는 이미지다.

## 구현 내용

### 공용 서비스

- 전체 작품 제목과 축약 회차 제목의 앞뒤 겹침을 비교해 `1~5화`, `141.5화`, `287화`와
  외전 부제를 분리한다. 실제 작품에서 잘린 R-18 미쿠·카나리아·히나타 표기도 복구한다.
- 신규 다운로드는 `전체 작품명 + 회차/부제` 폴더와 `0000.ext` 이미지명을 사용한다.
- 사이트 회차 제목이 비어 있거나 작품명만 반복되면 목록 순번으로 `N화`를
  만들지 않고 `unsafe_episode_title` 비재시도 오류로 중단한다.
- v1에 `innerHTML`로 남은 제목은 알려진 인라인 태그와 HTML 문자 참조를 표준화해
  현재 `textContent` 제목과 같을 때만 기존 폴더를 재사용한다.
- 신규 회차 목적지가 Windows 안전 길이를 넘으면 제목을 자동 축약하지 않고
  `path_too_long` 비재시도 파일 시스템 오류와 짧은 `-output` 안내를 남긴다.
- state v2에 게시물 순번, URL 경로 기반 source ID, URL, 사이트 원문, 전체 표시명과 실제
  폴더명을 저장한다. `completedEpisodes`는 v1 호환용으로 유지하고 안정 ID 완료 목록을
  함께 쓴다.
- 기존 폴더는 정확한 state 매핑, metadata 매핑, 숫자 접두어 순으로 찾는다. 숫자 접두어만
  있는 일반 사용자 폴더는 회차로 추측하지 않고, manifest에 없는 폴더는 구형 다운로더의
  `image####` 이미지 증거가 있을 때만 이관 대상으로 삼는다.
- 기존 긴 이미지 이름도 image index로 인식하되, 지원 확장자와 이미지 signature, JPEG/PNG
  종단 표식까지 유효한 파일만 건너뛴다. 0 byte·잘린 이미지·HTML 응답은 다시 받고, 새
  버퍼 검증이 끝난 뒤 같은 폴더의 임시 파일을 원자 교체한다. 이미지가 0개인 회차는 완료로
  기록하지 않는다.
- 두 manifest의 `episodes[]`가 없거나 손상돼도 metadata 제목 또는 `[작가][그룹] 제목`을
  NFC·Windows 경로 규칙으로 정규화한 뒤, 그 제목으로 시작하고 이미지가 직접 들어 있는
  폴더만 `modern-recovery`로 찾는다. 임의 사용자 폴더와 이미지 없는 메모 폴더는 제외한다.
- manifest 없는 복구 번호는 자연 정렬 순서에서 양수·고유하게 부여하되
  `numberInferred: true`로 표시하고 실제 회차 suffix, 표시명과 폴더명은 바꾸지 않는다.
  metadata 재생성은 이 매핑을 `episodes[]`로 영속화한다. 다음 사이트 검사에서는 순번이
  아니라 유일한 전체 회차명으로 폴더를 다시 연결한 뒤 실제 순번과 source ID로 승격한다.
- 회차 폴더가 있는데 state 파일이 없으면 파일 검사가 `state_missing`을 보고한다.
- 파일 검사, 미리보기, 중복 검사, 이미지 변환과 PDF가 같은 회차 탐색기를 사용한다.
- 기존 결과 이관은 전체 매핑과 충돌을 계산하는 읽기 전용 계획, 상태·메타데이터 백업,
  두 단계 임시 폴더명, 실패 롤백으로 구현했다. 이미지 파일은 이관 대상이 아니다.
- 이관은 오래된 같은 순번 record가 하나뿐이어도 원본 제목이 일치할 때만 ID를 승계한다.
  state나 명시 완료 목록이 없으면 물리 폴더만으로 완료를 추론하지 않으며, v2 완료 ID는
  그대로 보존하고 v1 숫자 완료는 신뢰 가능한 단일 identity에만 승격한다.

### GUI

- 작품 우클릭 `파일 및 회차 도구 > 회차 폴더명 정리...`를 추가했다.
- 변경 수와 앞쪽 매핑 예시를 먼저 보여주며, 충돌이 있으면 실행 버튼 경로로 들어가지 않는다.
- GUI 기능도 동일한 `rename-episodes` CLI와 IPC action으로 계획·실행할 수 있다.
- GUI/CLI 계획과 실행은 I/O worker로만 처리하고 동기 IPC 분기는 제거했다. dry-run은 현재
  화면의 작품을 불변 snapshot으로 넘겨 `jobs.db`를 읽거나 쓰지 않으며, execute만 GUI 이력을
  먼저 flush한 뒤 DB 기반 서비스로 실행한다.
- execute 응답 제한 시간을 넘기면 일반 실패와 달리 `operationMayContinue: true`와
  `statusCommand`를 반환해, 중복 실행 전에 백그라운드 작업 상태를 확인하도록 했다.
- 계획과 승인 후 실행 모두 공용 I/O 스레드 풀에서 처리해 수백 개 폴더를 검사하거나 바꾸는
  동안 Qt 메인 화면을 막지 않는다. 같은 작품의 중복 요청은 거부하고 우클릭 메뉴와 상태
  응답에 진행 중 상태를 표시한다.
- 정리 중 종료 요청은 작업을 강제 중단하지 않고 마지막 정리가 끝난 뒤 처리한다. CLI socket
  응답도 worker 완료 뒤 비동기로 전송한다.
- 실제 이름 변경 중에는 job ID뿐 아니라 work key와 정규화한 저장 경로를 기준으로 같은
  작품의 다운로드·재시도·메타데이터 쓰기·폴더 이동·이미지 변환·PDF 생성과 읽기 작업
  시작을 차단한다. 반대로 해당 작업이 실행/대기 중이면 이름 변경 실행을 차단하며, 다른
  작품의 대기 작업은 계속 시작할 수 있다. dry-run은 이 장기 배타 잠금을 잡지 않는다.

## 중요한 결정과 이유

- 선택: 사람이 보는 이름과 내부 회차 식별자를 분리했다.
- 이유: 게시물 순번은 실제 회차가 아니며 사이트 축약 제목은 폴더명 원본으로 사용할 수 없다.
- 선택: 이전 형식을 자동으로 일괄 변경하지 않고 명시 이관 명령으로 분리했다.
- 이유: 다른 작품의 기존 뷰어 계약을 갑자기 바꾸지 않고, 충돌을 전체 검사한 뒤 복구 가능한
  단위로 실행하기 위해서다.
- 선택하지 않은 대안: 모든 폴더 앞에 새 숫자 접두어를 붙이는 방식은 기존 감상 폴더 계약과
  다르고 외전·합본에서 다시 의미가 어긋나므로 사용하지 않았다.
- 동일 ordinal의 여러 안정 ID 중 기존 target 이름과 정확히 일치하는 record가 하나면 그
  identity를 이관 폴더에 연결한다. 둘 이상이 같은 folderName을 주장하거나 최종 manifest가
  parser-valid하지 않으면 `manifest_invalid` 충돌로 실행을 차단한다.

## 데이터와 보안 영향

- 사용자 다운로드 파일 변경 여부: 이 개발·검증 중 실제 작업에는 dry-run만 수행했다.
- 설정 또는 DB 마이그레이션: 없음. 작품별 state와 metadata만 명시 실행 시 v2 매핑을 쓴다.
- 쿠키·토큰·개인 경로 노출 여부: 없음.
- 되돌리는 방법: 명시 이관 전에 만든 state/metadata `.bak`과 반환된 source/destination
  매핑으로 복구할 수 있으며, 실행 도중 실패하면 서비스가 폴더와 JSON의 자동 복구를
  시도한다. 자동 복구까지 실패하면 `.toki-episode-rename-*.json`에 실제 위치를 남기고
  해당 경로를 수동 확인하기 전에는 다음 이관을 차단한다.

## 검증하지 않은 부분과 알려진 제한

- 사용자 확인 전이므로 실제 272개 폴더 이름변경은 실행하지 않았다.
- 사이트가 축약 과정에서 작품명뿐 아니라 고유 외전 부제까지 완전히 제거하면 원문만으로
  복구할 수 없다. 이 경우 충돌 discriminator와 state source ID가 데이터 손실을 막지만 표시명은
  사용자가 수정할 수 있는 후속 기능이 필요하다.
- 기존 이관은 폴더명과 매핑만 바꾸며 기존 이미지 파일명은 보존한다. 새 다운로드만
  `0000.ext` 형식을 기본으로 쓴다.
