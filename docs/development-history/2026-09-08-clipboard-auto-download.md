# 2026-09-08 — 복사한 작품 주소 자동 다운로드

기준선: `1aef421`, 브랜치 `codex/toki-gui-foundation`.

아래 최초 구현은 `389c2ea` 기준의 기록이다. 이후 사용자의 요청에 따라 기존 작품을
건너뛰는 동작을 새 회차 확인으로 변경했다. 현재 정책은 문서 마지막의 **후속 개선**을 따른다.

## 요청과 구현 범위

다른 앱에서 Ctrl+C로 작품 주소를 복사하면 실행 중인 다운로더가 확인창 없이 대기열에
추가하도록 요청받았다. 기존에는 감지가 꺼져 있었고, 켜더라도 확인창에서 수락한 뒤
입력창을 덮어쓰고 폼의 회차 범위로 실행했다.

- 공용 URL 판별은 `newtoki숫자.org/manhwa/양의 작품번호`의 정확한 HTTPS 목록 경로만
  허용한다. 사용자 정보·비표준 포트·위장 도메인·개별 회차 경로·다른 사이트는 거부한다.
- 페이지 쿼리와 fragment는 제거한다. 65,536자/앞쪽 32개 URL 상한, 복사 한 번당
  첫 지원 작품 하나라는 제한으로 대량 클립보드의 일괄 다운로드를 방지한다.
- 메모리의 작품 키 조회 및 DB 인덱스 조회로 화면에 로딩되지 않은 기존 작품까지 중복을
  검사한다. 작품 상태에 관계없이 중복은 제외한다. 메모리 키 전체를 매번 복사하지 않는다.
- 기존 `enqueue_download`를 재사용한다. 폼의 URL/회차 범위를 변경하지 않고 저장된
  기본 폴더·연결 수·재시도·브라우저 설정을 사용한다. 회차 제한 없는 신규 회차 검사로
  등록하며, 작업 완료 후 작품 전체 ZIP/원본 정리도 기존 설정을 그대로 따른다.
- Qt 클립보드 변경 신호를 사용하므로 앱이 최소화되어 있거나 우클릭으로 복사해도
  동작한다. Ctrl+C를 전역 후킹하거나 클립보드를 주기적으로 폴링하지 않는다.
- 반복 이벤트 및 확인창 도중 재진입을 방지하고, 중간에 복사된 최신 값을 확인창이
  닫힌 뒤 처리한다. 원본 클립보드 텍스트 대신 길이가 고정된 해시만 보관한다.
- 등록 실패를 성공으로 보고하지 않는다. 큐/폴더/DB 오류는 예외로 GUI를 종료시키지 않고
  로그와 `lastInspection`에 실패 결과를 남긴다. 무관한 텍스트는 로그에 저장하지 않는다.

## 설정·GUI·CLI

설정 스키마는 30으로 갱신했다. `clipboardMonitor`와 새 `clipboardAutoDownload`를
분리해 기존 사용자 설정의 확인 동작을 보존한다. 기본값은 둘 다 false이다.
사용자의 실행 환경에는 검증 후 감지와 자동 추가를 모두 켰다. 기본 저장 경로와 압축 정책은
바꾸지 않았다. 구버전 GUI가 새 설정 스키마를 읽지 않도록 새 코드로 재시작했다.

설정 → 일반에 감지 체크박스와 `확인 후 추가 / 확인 없이 자동 다운로드` 선택을 제공한다.
감지가 꺼지면 방식 선택을 비활성화한다. 저장/불러오기/설정 검색에도 연결했다.

```powershell
.\toki-cli.cmd clipboard monitor --state on --mode auto --json
.\toki-cli.cmd clipboard monitor --state on --mode confirm --json
.\toki-cli.cmd clipboard monitor --state off --json
.\toki-cli.cmd clipboard status --json
.\toki-cli.cmd clipboard inspect --text "https://newtoki1.org/manhwa/34360" --via-gui --json
.\toki-cli.cmd clipboard enqueue --text "https://newtoki1.org/manhwa/34360" --yes --json
```

`inspect`는 자동 감지가 켜져 있어도 읽기 전용이다. `enqueue`는 명시적인 `--yes`가
있을 때만 실제 등록하며, 감지 설정과 독립적으로 같은 검증/등록 경로를 사용할 수 있다.

## 제한 및 변경하지 않은 사항

- 복사 시 판정은 주소 형식 검사이다. 실제 사이트가 열리는지, 회차가 있는지는 다운로더가
  실행 시 검사한다. 이 기능 검증을 위해 실제 사이트에서 새 작품을 내려받지는 않았다.
- 레거시 URL은 목록과 개별 회차를 주소만으로 구분하기 어려워 자동 감지 대상에서 제외한다.
  기존 수동 다운로드 기능의 지원 범위는 변경하지 않았다.
- 기존 완료/오류 작품 갱신은 재시도 버튼을 사용한다. URL을 복사해서 중복 재시도를 만들지 않는다.
- 프로그램 시작 또는 감지 설정 변경만으로 이미 있던 클립보드를 다운로드하지 않는다.
- 사용자 다운로드 파일 이동/삭제나 작업 기록 변경은 하지 않았다. 이미 알려진 별도 작품의
  회차 제목 인식 오류는 이번 클립보드 기능 범위에 포함하지 않았다.

## 후속 개선 — 기존 작품 주소 복사 시 새 회차 확인

기준선: `389c2ea`. 사용자는 이미 등록된 작품을 단순히 무시하는 대신 기존 목록을
새로고침하는 동작을 요청했다.

- 완료·오류·중지·취소 등 비활성 작품은 같은 작품 목록 한 줄을 유지하면서 회차 목록을
  다시 수집하는 신규 회차 검사(`scan_mode=new`, 시작/끝 제한 없음)를 예약한다.
  `rescan_job_parameters`와 기존 `enqueue_download`를 재사용한다.
- 기존 작품의 출력 폴더·표지·메타데이터·메모·고정 표시를 이어받고, 실행 이력만 추가한다.
  전역 기본 폴더가 달라져도 기존 작품을 다른 폴더에 재다운로드하지 않는다.
- 복사한 주소의 호스트 번호가 달라졌다면 최신 복사 주소를 사용하되 작품 키는 유지한다.
- 실행·대기·재시도 대기·일시정지 작품은 `already_active`로 반환하고 추가 실행하지 않는다.
  압축·삭제·폴더 정리와의 충돌은 기존 공통 실행 보호 장치를 유지한다.
- 확인 방식에서는 기존 작품의 새 회차 확인이라는 문구를 표시한다. 대화상자 도중 다른
  요청으로 상태가 바뀌어도 직전에 재검사해서 활성 작업을 중복 등록하지 않는다.
- 클립보드 해시가 같다는 이유로 사용자의 다음 복사를 영구 무시하지 않는다. 실제 변경
  신호와 내부 지연 재검사를 구분해, 완료 후 동일 텍스트 재복사는 갱신하되 내부 콜백이
  스스로 갱신을 반복하는 현상은 방지한다.
- `clipboard inspect`는 계속 읽기 전용이다. 실제 등록 API는 `refreshed`와
  `refresh_queued`/`new_queued`/`already_active`로 실행 여부를 구분한다.
- README, 설정 화면 설명과 CLI 도움말에도 현재 정책을 반영했다.
