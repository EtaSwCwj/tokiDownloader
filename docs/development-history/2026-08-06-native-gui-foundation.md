# 2026-08-06 네이티브 GUI와 공용 다운로드 기반

## 기준

- 날짜: 2026-08-06
- 커밋: 3599e3d
- 변경 규모: 12개 파일, 2,406줄 추가, 65줄 삭제

## 해결하려던 문제

1. newtoki 숫자.org/manhwa/작품번호 형식의 URL을 기존 코드가 거부했다.
2. 명령행만으로 URL과 회차를 넣는 방식은 반복 사용하기 어려웠다.
3. 작품이 작가·그룹·제목 정보 없이 저장되고 저장 기준 폴더도 고르기 어려웠다.
4. 대표 이미지와 metadata.json을 작품 폴더에 함께 보존할 필요가 있었다.
5. 오류를 사용자가 확인하고 모든 GUI 동작을 CLI에서도 재현할 수 있어야 했다.
6. 브라우저와 콘솔 창이 계속 보이는 실행 방식은 일상적인 PC 사용을 방해했다.

## 구현 내용

### URL과 다운로드 엔진

- newtoki 숫자.org/manhwa/작품번호 URL 정규식을 추가했다.
- 해당 주소를 기존 마나토끼 계열 처리 경로와 연결했다.
- 구형 지연 로딩 속성과 신형 CDN 이미지 주소를 함께 처리했다.
- 저장 기준 폴더를 받는 output 옵션과 기계 판독 가능한 JSON 이벤트를 추가했다.

### 폴더와 메타데이터

- 기본 작품 폴더명을 [작가][그룹] 제목 형식으로 정규화했다.
- Windows 금지 문자와 빈 메타데이터에 대한 대체 규칙을 넣었다.
- 작품 폴더에 metadata.json과 대표 이미지를 저장하는 경로를 추가했다.
- 기존 회차 파일은 다시 내려받지 않는 구조를 유지했다.

### 공용 구조

- toki_core.py: 작업 상태, 설정, 로그와 공용 서비스
- toki_app.py: GUI와 동일한 기능을 호출하는 CLI 및 IPC 진입점
- toki_gui.py: PyQt6 네이티브 Windows GUI
- down.js: 실제 Node/Puppeteer 다운로드 작업자와 이벤트 출력

GUI와 CLI가 각자 다운로드 로직을 구현하지 않고 같은 서비스와 작업자 경로를 사용하도록
기초를 잡았다.

### 실행과 관측성

- GUI 실행 스크립트와 CLI 래퍼를 추가했다.
- 화면 로그와 파일 로그를 함께 남기는 기반을 추가했다.
- URL, 회차 범위와 저장 폴더를 GUI에서 입력할 수 있게 했다.
- 작업 대기열, 진행 상태와 오류를 GUI에서 확인할 수 있게 했다.

이 시점의 Puppeteer 연결은 아직 headless:false였고 Chrome 표시·숨김 선택 기능은 없었다.
숨김 브라우저와 숨김 작업자는 다음 날 후속 커밋에서 구현했다.

## 사용자에게 생긴 변화

명령어를 직접 조립하지 않아도 Windows 창에서 작품 URL과 저장 위치를 지정할 수 있게 됐다.
폴더 이름과 메타데이터가 작품 단위로 보존되고, 이후 목록·이력·재시도 기능이 같은 작품
식별자를 중심으로 발전할 수 있는 기반이 생겼다.

## 당시 남아 있던 문제

- 초기 목록은 job_id별 실행을 별도 행으로 늘렸으며, 여러 실행을 작품 한 행으로 통합하고
  별도 실행 이력으로 누적하는 구조가 아직 없었다.
- 실행 이력, 전체 재검사, 신규 회차 검사와 범위 재검사의 의미가 아직 충분히 나뉘지 않았다.
- 대규모 목록 성능, 제한된 스레드·프로세스 풀과 큐 백프레셔가 후속 작업으로 남았다.
- 창 위치 복원, 우클릭 메뉴, 더블클릭 폴더 열기와 고유 작업 표시줄 ID가 필요했다.
- Chrome과 작업자 콘솔을 기본적으로 보이지 않게 실행하는 처리가 필요했다.
- 선택형 Hitomi와 YouTube 공급자 기능은 아직 없었다.

이 항목들은 다음 날의 작품 단위 저장소와 단계별 확장 작업에서 보완했다.
